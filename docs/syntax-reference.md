# Syntax reference

How to write a template file for `md-template-lint`, in one page for agents. A template is a
Markdown file that is also the schema: frontmatter keys define fields, headings define
sections, and bracket tags in comments and heading suffixes define the rules. The contract is
[spec.md](spec.md); it wins over this page. The tables below (tags, type hints, error codes by family and by code, enums)
are generated by `pnpm run gen:syntax-doc` from the grammar, the rule registry and the source.
Do not edit them by hand; `pnpm run check:syntax-doc` fails when they are stale.

## Minimal template

```yaml
---
# [filename:case:kebab-case]
id: "string" # [presence:required] [value:filename]
owner: "string" # [presence:optional]
tags: ["a"] # [count:min:1] [format:elements:kebab-case]
version: "1.0.0" # [format:semver]
released: "2026-01-31" # [date] [format:date]
---

# Title

## Overview [presence:required] [content:non-empty]

### Background [presence:optional]

## Release [pattern:"{semver} - {date}"] [repeat-rules:same-level] [order:first:semver:descending]

## Authoring checklist [presence:template-only]
```

## Where tags go

A tag is `[family:argument...]`. Keywords are case-insensitive; only
`[filename:case:<convention>]` is case-sensitive. Several tags may share one comment, mixed
with free text, in any order. For a tag that can appear once, the first one wins. Text and
tags in a target file are inert; only recognized trailing heading tags are stripped from
target headings before comparison.

| Region      | Where                                                                                | Binds to              |
| ----------- | ------------------------------------------------------------------------------------ | --------------------- |
| frontmatter | Trailing `#` comment of a top-level key line (`key: value # [tag]`)                  | that key              |
| frontmatter | Standalone `#` comment line holding only the tag (`filename`, `unique-headings-names`) | the whole template  |
| heading     | Bracket tags after the text of a heading of any level H1 to H6 (`## Text [tag]`)     | that heading          |

- A `#` starts a comment only outside quotes and at the start or after a space or tab.
- Comments on indented sub-keys and on list items bind to nothing.
- A known tag in the wrong region is `MTL013` (warning). A bad argument (`[count:min:abc]`) is
  `MTL012`. An unknown bracket that looks like a tag is `MTL010` (field, or a standalone
  frontmatter comment line, even `# [todo]`; to keep a note, write it without square brackets) or
  `MTL011` (heading). These template warnings show with `--verify` only.
- Heading tags are peeled from the right while they are recognized; the first unrecognized
  bracket stays in the heading text.
- Heading text is compared exactly (case-sensitive) and the level must match exactly.
- A heading or a field without `presence` tag is required. Headings inside fences are ignored.

### Tag forms

`N` is a number, `<text>` free text up to `]`, `<schemes>` a comma-separated list, `<pattern>` a
quoted pattern. Tags in the table are the complete set of the grammar. Where one form is
written `[a:b:c]`, every colon part is a literal keyword.

Notes on specific families:

- `count:min:N` and `count:max:N`: N is a non-negative integer. `range:min:N` and `range:max:N`:
  N is `-?digits` with an optional `.digits`. They are never interchangeable.
- `format:constant:<text>` (value equals `<text>`) and `format:scheme:<schemes>` (comma separated,
  for `url` and `list-of-url` fields).
- `format:date` and `format:elements:date` mean a real `YYYY-MM-DD` date. `format:semver` has no
  `v` prefix. Case styles: `snake_case`, `kebab-case`, `camelCase`, `PascalCase`.
- `io:exists` works on `path`, `list-of-path`, `url`, `list-of-url`; all findings are warnings.
- `order:ascending` on a frontmatter key orders a `list-of-date`; on a heading it orders the
  repeats of a pattern heading (`MTL407` versus `MTL609`).
- `content:subheadings:disallow` forbids unlisted headings in the whole subtree.
  `content:subheadings:no-extra` forbids undeclared direct children only.
- `presence:conditional:<text>` is documentation only and behaves like optional.
- `presence:template-only` is guidance in the template; the same heading in a target is an error.
- `unique-headings-names` ignores case (lowercase folding) and heading level.
- Without a presence tag a repeat heading needs at least one instance. Explicit
  `repeat-rules:same-level:min:N` and `max:N` need N of 1 or more.
- `order:` on a pattern heading needs a `repeat-rules` tag (else `MTL030`); on a heading with
  no pattern it has no effect (`MTL015`).
- `[presence:exist]` was removed; use `[pattern:"{text}"]` for "any heading here".

### Heading patterns

`[pattern:"..."]` replaces the heading text by a pattern: literal text plus placeholders. In the
pattern, `{{` and `}}` are literal braces, `\"` a literal quote, `\\` a literal backslash, any other
backslash pair is `MTL014`. No `v` prefix is implied: write `v{semver}` when headings carry one.
Two placeholders may not touch (`{digits}{text}` is `MTL014`); put literal text between them.

| Placeholder | Default value                                         | Other formats (`{name:format:<fmt>}`)                              |
| ----------- | ----------------------------------------------------- | ------------------------------------------------------------------ |
| `{text}`    | any text except a purely numeric value                | `snakecase`, `camelcase`, `screamcase`, `kebabcase`, `lowercase`, `uppercase` |
| `{number}`  | `-?digits(.digits)?`, leading zeros allowed           | `scientific`, `precision:N`                                        |
| `{digits}`  | `0` or digits with no leading zero, no sign           | `signed`, `hex`, `uid`, `padding:N`                                |
| `{semver}`  | full SemVer 2.0.0                                     | `core`, `major-minor`                                              |
| `{date}`    | `YYYY-MM-DD`, a real date                             | `year-month`, `year`                                               |
| `{char}`    | one Unicode letter (no format allowed)                | none                                                               |

An argument (`padding:3`, `precision:2`) is digits of 1 or more with no leading zero. A pattern
heading, optionally with a repeat tag, takes the next sibling or run of siblings that match. Order
keys of `order:first:...` are the first number, ISO date or semver found in the heading text.

## Type hints

Type hints choose the field type; they are not rules. Without a hint the type is inferred from the
value. Forms of a hint, in the inline comment:

- a single-word bracket, `[date]`, `[path-alias]`, `[list-of-int]` (`rating: "3" # [int]`);
- the text `YYYY-MM-DD` or `ISO` (date); the words `url`, `lien` (url) or `path` (path);
- an alias marker `@name/` (path-alias);
- the field value equal to a type name (`"date"`) or an option list `a | b` (enum).

Colon tags such as `[presence:...]` never act as a type hint, and the text `type=<name>` in a
comment is plain text, not a hint. There is no `list-of-enum`;
`list-of-string` and `list-of-int` exist only through an explicit hint. A hint that is not one of
the types is kept as a name, never validated, and the bracket is also `MTL010`.

## Disable directives (target files only)

A target file silences codes locally. Directives are never read in a template, inside fenced code
or inline code, or after a parse error. Keyword, verbs and codes are case-insensitive.

| Directive                                      | Covers                                                    |
| ---------------------------------------------- | --------------------------------------------------------- |
| `md-template-lint disable <codes>`             | its line to the matching `end disable`, else to the end of the file |
| `md-template-lint disable-line <codes>`        | its own line                                              |
| `md-template-lint disable-next-line <codes>`   | the next file line                                        |
| `md-template-lint disable-file <codes>`        | the whole document, including findings without a line     |
| `md-template-lint begin disable <codes>`       | its line to the matching `end disable` (unclosed is `MTL024`) |
| `md-template-lint end disable <codes>`         | closes the open range of each listed code                 |

- Carriers: a one-line HTML comment in the body (`<!-- md-template-lint disable-line MTL701 -->`,
  also on a heading line) and, in the frontmatter, a YAML comment (trailing a top-level key line, or
  a whole-line comment with `#` in column 1).
- Codes are separated by commas or spaces. A free-text reason follows a lone `--`.
- Suppressible range: `MTL101` to `MTL899` only. Everything else is not suppressible and gives
  `MTL022` when named: `MTL001`-`MTL004`, `MTL010`-`MTL019`, `MTL020`-`MTL025`, `MTL030` and the run
  codes `MTL900`-`MTL999`.
- There is no wildcard. A directive with no code is `MTL020`; an unknown code is `MTL021`.
- The keyword is always `md-template-lint`, whichever command name (`mdtl` or `md-template-lint`) runs
  the tool.
- A diagnostic without a line (the file name, a missing key, a missing heading, the heading order) is
  covered only by `disable-file`. A range or a line directive never covers it.
- A directive comment in the body counts as a non-blank line of its section for `MTL701`, `MTL704` and
  `MTL705`; put a directive about a section on its heading line.
- The directive warnings are `MTL020` to `MTL025`. They are never suppressible and never change the exit
  code.

### Complete example

A runnable project of three files: a config, a template and a target. The target uses all six directive
forms. Each file is the fenced block that follows its `File:` line, in this order. Run it from the folder
that holds the config with `mdtl` (or `mdtl --format plain`).

File: `md-template-lint.yml`

```yaml
pairs:
  - template: templates/note.template.md
    include: docs/*.md
```

File: `templates/note.template.md`

```yaml
---
title: Notes
status: draft
version: "1.0.0" # [format:semver]
---

# Notes

## Overview [content:non-empty]

## Details [content:non-empty]

## Context [content:non-empty]

## Summary
```

File: `docs/note.md`

```yaml
---
title: Notes
status: draft
owner: alice # md-template-lint disable-line MTL202
# md-template-lint disable-next-line MTL202
reviewer: bob
# md-template-lint begin disable MTL202
legacy_id: 42
legacy_owner: alice
# md-template-lint end disable MTL202
# md-template-lint disable MTL306
version: "1.0"
# md-template-lint end disable MTL306
extra: x
---

<!-- md-template-lint disable-file MTL601 -- Summary is added later -->

# Notes

## Overview <!-- md-template-lint disable-line MTL701 -->

## Details

## Context

Some text.
```

What each directive does in `docs/note.md`:

- `disable-line MTL202` (line 4, a trailing YAML comment): covers its own line, the unknown key `owner`.
- `disable-next-line MTL202` (line 5): covers line 6, the unknown key `reviewer`.
- `begin disable MTL202` ... `end disable MTL202` (lines 7 to 10): cover the unknown keys `legacy_id` and
  `legacy_owner`. Without the `end disable` line the range would run to the end of the file and give
  `MTL024`.
- `disable MTL306` ... `end disable MTL306` (lines 11 to 13): the open form. It covers the bad semantic
  version of `version` (line 12) and is closed by `end disable`. Left unclosed, it would run to the end
  of the file without a warning.
- `disable-file MTL601` (line 17, an HTML comment; a reason follows the lone `--`): covers the missing
  heading `Summary`, a diagnostic without a line, wherever the directive stands.
- `disable-line MTL701` on the heading line `## Overview`: covers the empty section `Overview`.

Without the directives the file gives nine diagnostics. Seven are suppressed (four `MTL202`, one
`MTL306`, one `MTL701`, one `MTL601`), so the summary shows `Suppressed:   7`. Two remain and are
printed. The expected remaining diagnostics, in this order, are:

- `MTL701` (error): `Section 'Details': [content:non-empty] section body is empty` (line 23).
- `MTL202` (warning): `Unknown key 'extra' not present in template` (line 14).

The run exits 1 (one error remains). No directive warning (`MTL020` to `MTL025`) is printed.

## Error codes

`pnpm run check:rules` pins this table to the registry and to `docs/spec.md` section 4.3. Severity
`warning` never changes the exit code. Codes are never renumbered or reused (a change needs a PR discussion and a breaking-change note);
`MTL602` is retired and stays reserved.
Run codes (`MTL9xx`) are not rules; they report problems of the run itself.
