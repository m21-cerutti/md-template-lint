## Configuration and runs

| Term          | Definition                                                                                                                                                                                                                                  | See also                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| alias         | A named directory of the config (`aliases`, `LintConfig.aliases`, `RuleEnv.aliases`). A path value that starts with `@name/` is resolved through it by `[io:exists]` (`ALIAS_LIKE` in `src/engine/values.ts`, rules `MTL801` and `MTL802`). | [spec 2.8](spec.md#28-the-ioexists-tag)                               |
| approvedPaths | The config key (`LintConfig.approvedPaths`, `RuleEnv.approvedPaths`) that lists the absolute directories `[io:exists]` may check. An absolute path outside them is skipped with `MTL803`.                                                   | [spec 2.8](spec.md#28-the-ioexists-tag)                               |
| pair          | One entry of `pairs` in `md-template-lint.yml` (`PairConfig`): a template, include and exclude globs and the roots it runs on. In the tests a "pair fixture" is a folder with one `template.md` and one `target.md`.                        | [spec 6.3](spec.md#63-schema)                                         |
| `--verify`    | The CLI mode that parses templates only and prints their schema and tag warnings (`verifyConfig`, `verifyPaths` in `src/runner/verify.ts`, `describeTemplate` in `src/runner/schema.ts`). It reads no target and builds no io.              | [spec 7.3](spec.md#73---verify), [CLI flowchart](architecture.md#cli) |

## Templates, targets and tags

| Term                 | Definition                                                                                                                                                                                                                                                                                                                                                                                                    | See also                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| disable directive    | A comment in a target that silences rule codes locally (`<!-- md-template-lint disable-line MTL201 -->` in the body, `# md-template-lint ...` in the frontmatter). The parsed form is `Directive` (verb type `DirectiveVerb`, `src/tags/ast.ts`); the engine validates it and builds a `SuppressionPlan` (`src/engine/directives.ts`). Problems are `MTL020` to `MTL025`.                                     | [spec 4.4](spec.md#44-disable-directives-in-target-files)                                                       |
| frontmatter optional | The template tag `# [frontmatter:optional]`, a standalone comment line in the template frontmatter. A target without a frontmatter block then gets no `MTL001` and no field rule; filename, heading and content rules still run. In code: the flag `frontmatterOptional` of `Frontmatter` and `DocumentModel`, and the option of `loadDocument(text, { frontmatterOptional })` that only `lintTarget` passes. | [spec 2.12](spec.md#212-optional-frontmatter-frontmatteroptional), [ADR 0015](adr/0015-optional-frontmatter.md) |
| region               | The part of a document a tag is written in (the type `Region`, `"frontmatter"` or `"body"`, in `src/tags/ast.ts`). The lexer has region modes too (`FM*`, `BODY*`).                                                                                                                                                                                                                                           | [lexer modes](architecture.md#lexer-modes)                                                                      |
| tag                  | A bracket token `[family:argument]` in a field comment or a heading suffix, for example `[count:min:2]`. Well-formed tags become typed data (`FrontmatterTag`, `BodyTag` in `src/tags/ast.ts`); problems become `TagFinding`.                                                                                                                                                                                 | [spec 2](spec.md#2-template-tags)                                                                               |
| target               | A Markdown file linted against one template. Tags in a target are inert; it may carry disable directives.                                                                                                                                                                                                                                                                                                     | [spec 1.1](spec.md#11-what-a-template-is)                                                                       |
| template             | A Markdown file that is the schema: its frontmatter keys, inline comments and heading suffixes carry the tags. It is parsed once per run and never linted against itself.                                                                                                                                                                                                                                     | [spec 1.1](spec.md#11-what-a-template-is)                                                                       |

## Headings and sections

| Term           | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | See also                                                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Checked        | A heading the rules look at. Every file-scope template heading is checked. A section-scope template heading is checked only when its template parent is checked, is not `[presence:template-only]` and has a match. A heading that is not checked gives no finding of any code, and neither do its section-scope descendants. A heading with an invalid pattern (`MTL014`) is never checked.                                                                                                                                                                       | [grammar: Checked](grammar.md#terms-used-by-the-rules)                                                                                                                           |
| Extra          | A sibling left after the last position of a sequence (the tail). An extra never fails the target by itself; a run with extras gives one warning `MTL616` (heading-extra) that lists them. A tail sibling that an error already names (`MTL612`, `MTL614`, `MTL615`) is left out of that list. A level and scope with no position has no run, so it has no extras.                                                                                                                                                                                                  | [grammar: Extra](grammar.md#terms-used-by-the-rules), [spec 2.10](spec.md#210-heading-patterns-repeat-rules-and-order)                                                           |
| Match of T     | The sibling the position of a template heading T took. Matching is positional: the positions of one sequence take the siblings of one scope in order, as one adjacent run, greedy first-fit with no backtracking. For a repeat heading each instance is a match. A template heading without a match is "missing"; its presence tag decides whether that is an error.                                                                                                                                                                                               | [grammar: Match of T](grammar.md#terms-used-by-the-rules), [ADR 0012](adr/0012-positional-heading-matching.md), [spec 2.10](spec.md#210-heading-patterns-repeat-rules-and-order) |
| Parent         | The template parent of a template heading is the nearest template heading before it with a lower level; a heading with none has no template parent. The target parent of a target heading is defined the same way, in the target. The subtree of a template heading is every template heading after it up to the next one of the same or a lower level.                                                                                                                                                                                                            | [grammar: Parent](grammar.md#terms-used-by-the-rules)                                                                                                                            |
| Position       | One member of a sequence. Each position takes zero or more siblings from the current point onward, never skips a sibling and never goes back.                                                                                                                                                                                                                                                                                                                                                                                                                      | [grammar: Sequence](grammar.md#terms-used-by-the-rules), [spec 2.10](spec.md#210-heading-patterns-repeat-rules-and-order)                                                        |
| scope          | Which target headings are the siblings the position of a template heading can take (`HeadingMatch.scope` in `src/engine/model.ts`). `file` for H1, H2 and a heading with no template parent: the siblings are the target headings of that level in the whole file. `section` for H3 to H6 with a template parent: the siblings are the target headings of that level inside the matched section of that parent. A heading is matched by position, not searched by text: the positions of one level and scope take the siblings in file order, as one adjacent run. | [grammar: Scope](grammar.md#terms-used-by-the-rules), [heading and section model](architecture.md#heading-and-section-model)                                                     |
| section        | A heading of any level (H1 to H6) with its text, tags, body and parent (`Section` in `src/engine/model.ts`). The parent is the nearest preceding heading with a lower level. Levels match exactly.                                                                                                                                                                                                                                                                                                                                                                 | [spec 2.6](spec.md#26-heading-suffix-tags-body-sections)                                                                                                                         |
| Sequence       | The list, in template order, of the template headings of a heading T's level that share T's scope. `[presence:template-only]` headings and headings that are not checked are left out. Each member is a position.                                                                                                                                                                                                                                                                                                                                                  | [grammar: Sequence](grammar.md#terms-used-by-the-rules), [spec 2.10](spec.md#210-heading-patterns-repeat-rules-and-order)                                                        |
| Siblings       | The target headings of one level in one scope, in file order. In section scope there is one set of siblings per match, or per instance, of the template parent.                                                                                                                                                                                                                                                                                                                                                                                                    | [grammar: Siblings](grammar.md#terms-used-by-the-rules)                                                                                                                          |
| Target section | The target section of a target heading at level n is its own line and every following line up to the next target heading of level n or lower, or the end of the file. A deeper target heading lies "inside" it when its line is in this range.                                                                                                                                                                                                                                                                                                                     | [grammar: Target section](grammar.md#terms-used-by-the-rules)                                                                                                                    |

## Patterns and placeholders

| Term        | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | See also                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| pattern     | The whole expected text of a template heading, written in the tag `[pattern:"..."]`. It must match the entire heading text of a target heading, not a part of it. Text outside placeholders is literal, so `## Changes` and `## [pattern:"Changes"]` are the same, and `## [pattern:"{semver} - {date}"]` matches `## 1.2.0 - 2026-10-01`. A pattern is made of literal text and placeholders. The text written before the tag in a template heading (`## Release [pattern:...]`) is a hint for authors only; the pattern decides what matches. Escapes: `\"` for a double quote, `\\` for a backslash, `{{` and `}}` for literal braces. Not a regular expression (a regexp pattern is only an idea).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | [spec 2.10](spec.md#210-heading-patterns-repeat-rules-and-order) |
| placeholder | A variable slot inside a pattern, written `{name}` or `{name:format:<fmt>}`. The vocabulary is fixed: `{semver}`, `{date}`, `{digits}`, `{number}`, `{text}` and `{char}` (one letter). A placeholder stands for one value of its kind (`{digits}` matches `7`, `{text}` matches `Release notes` but not `2026`); the optional `format` narrows it (`{semver:format:major-minor}` matches `1.2`, `{text:format:snakecase}` matches `my_heading`). A format may take an argument, `{name:format:<fmt>:<arg>}` (`{digits:format:padding:3}` matches `007`, `{number:format:precision:2}` matches `1.50`). Formats: `{digits}` default, `signed`, `hex`, `uid`, `padding:N`; `{number}` `decimal` (default), `scientific`, `precision:N`; `{text}` `human` (default), `snakecase`, `camelcase`, `screamcase`, `kebabcase`, `lowercase`, `uppercase`; `{semver}` `full`, `core`, `major-minor`; `{date}` `full`, `year-month`, `year`. Everything in a pattern outside placeholders is literal. A placeholder is not a pattern: `{text}` alone is the pattern "any non-numeric text", and `Epic {char} - {text}` is a pattern with two placeholders. An unknown name, format or a wrong argument is `MTL014`. An order tag on a repeat-less heading is `MTL030`. | [spec 2.10](spec.md#210-heading-patterns-repeat-rules-and-order) |

## Rules, codes and diagnostics

| Term                                | Definition                                                                                                                                                                                                                                                                                                                                                                                                    | See also                                                          |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| anchor line                         | The one target line a diagnostic is about, or none (`anchorLineOf` in `src/engine/rule.ts`). It lives in a side table, not on the `Diagnostic`; a disable directive covers a diagnostic by its code and anchor line, and the runner quotes the anchored line.                                                                                                                                                 | [anchor lines](architecture.md#anchor-lines-spec-44-dir5)         |
| category                            | One of the nine groups of rules (`CATEGORIES`, the type `Category` in `src/engine/rule.ts`): `syntax`, `filename`, `presence`, `format`, `bounds`, `type`, `heading`, `content`, `io`. Each has one file `src/rules/<category>.ts` and one code range.                                                                                                                                                        | [where the codes live](architecture.md#where-the-codes-live)      |
| conflicting tag (`MTL015`)          | A well-formed heading tag that can have no effect, for example `[content:subheadings:disallow]` on a `[presence:template-only]` heading. A template warning shown by `--verify` in the section `Conflicting tags:`.                                                                                                                                                                                           | [spec 2.7](spec.md#27-inert-unknown-and-malformed-tags)           |
| date format missing (`MTL016`)      | A template field of type `date` without `[format:date]`, or of type `list-of-date` without `[format:elements:date]`. A template warning shown by `--verify` in the section `Date fields without format:`; never suppressible.                                                                                                                                                                                 | [spec 2.9](spec.md#29-field-formats-formatsemver-formatdate)      |
| frontmatter tag conflict (`MTL031`) | A well-formed `[frontmatter:optional]` that has no effect: a later duplicate line, the tag after a key, or the tag in mixed comment text. A template warning shown by `--verify` in the section `Conflicting frontmatter tags:`; never suppressible.                                                                                                                                                          | [spec 2.12](spec.md#212-optional-frontmatter-frontmatteroptional) |
| misplaced tag (`MTL013`)            | A well-formed tag written in the wrong region, for example a heading tag in a field comment. The finding reason in code is `wrong-region` (`TagFindingReason`); the rule is `misplaced-tag`. It is a warning.                                                                                                                                                                                                 | [spec 2.7](spec.md#27-inert-unknown-and-malformed-tags)           |
| MTL code                            | The stable identifier `MTL` plus three digits of a rule or a run diagnostic (the type `RuleCode`, `codeNumber` in `src/engine/model.ts`). The range tells the category; a code is never renumbered or reused.                                                                                                                                                                                                 | [spec 4.3](spec.md#43-code-table)                                 |
| phase                               | When the pipeline runs a rule (the type `Phase` in `src/engine/rule.ts`): `parse`, `template`, `field` or `target`. `field` and `target` rules also have a step.                                                                                                                                                                                                                                              | [rule contract](architecture.md#rule-contract)                    |
| rule                                | One check with a code, name, severity, category, phase and a `check` function (`defineRule`, `AnyRule` in `src/engine/rule.ts`), registered through `src/rules/<category>.ts`. Not a run diagnostic.                                                                                                                                                                                                          | [rule contract](architecture.md#rule-contract)                    |
| run diagnostic vs run warning       | A run diagnostic (`RunDiagnostic`, `src/config/types.ts`) is a `MTL9xx` finding about the run itself (config, a missing root, template or target, usage), not a rule. A run warning is one of them with severity `warning` (`RunResult.runWarnings`; only `MTL913` with `onEmpty: warn`): it never changes the exit code, while a run error (`runErrors`) gives exit 2. There is no type named "run warning". | [spec 4.3](spec.md#run-errors-engine-no-rule-file)                |
| severity                            | `error` (the file fails, exit 1) or `warning` (printed, never changes the exit code); the type `Severity` in `src/engine/model.ts`.                                                                                                                                                                                                                                                                           | [spec 1.3](spec.md#13-severity)                                   |
| shape (field step)                  | The last `field` step (`"shape"` in `FIELD_STEPS`, `src/engine/rule.ts`), run after `type`. It holds the format shape checks `MTL306` to `MTL309` (`[format:semver]`, `[format:date]` and their `elements:` forms). Not the value shape in the type rules.                                                                                                                                                    | [spec 2.9](spec.md#29-field-formats-formatsemver-formatdate)      |
| source excerpt                      | The bounded window of the source line a diagnostic is about, printed under it with a caret (`SourceExcerpt` in `src/runner/types.ts`, `withExcerpts` in `src/runner/excerpt.ts`, `excerptRows` in `src/reporters/excerpt.ts`; JSON `sourceLine`).                                                                                                                                                             | [runner and config](architecture.md#runner-and-config)            |

## Parser and engine

| Term                | Definition                                                                                                                                                                                                                                          | See also                                                                         |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| DiagnosticCollector | The class (`src/tags/listeners.ts`) that is the single sink of one document parse: it holds the `GrammarError` list and the `TagFinding` list.                                                                                                      | [listeners and error flow](architecture.md#listeners-and-error-flow)             |
| DocumentModel       | The interface (`src/engine/model.ts`) of one loaded template or target: its `fields`, `sections`, filename tag, tag `findings` and `directives`, built by `loadDocument`.                                                                           | [data flow](architecture.md#data-flow)                                           |
| generated parser    | The lexer, parser, listener and visitor in `src/generated/`, written by `pnpm run gen:parser` from the two grammars, checked by `pnpm run check:parser`, never hand-edited.                                                                         | [the generated parser](guides/grammar-and-listeners.md#the-generated-parser)     |
| lexer mode          | A state of the ANTLR lexer in `grammar/MdTemplateLexer.g4` (`DEFAULT_MODE`, `FM`, `BODY`, `TAG_STRICT`, `DIRECTIVE`, ...). The modes separate the regions of a document and the parse stages.                                                       | [lexer modes](architecture.md#lexer-modes)                                       |
| listener            | An ANTLR object called during lexing, parsing or a tree walk. Here: the error listeners `LexerErrorListener` and `ParserErrorListener` (`src/tags/listeners.ts`) and the tree listener `TypeHintListener` (`src/tags/visitors/hints.ts`).           | [listeners and visitors](guides/grammar-and-listeners.md#listeners-and-visitors) |
| TagFinding          | The interface (`src/tags/ast.ts`) of one tag problem: region, reason (`unknown`, `malformed` or `wrong-region`), the bracket text and its position. `src/rules/syntax.ts` turns findings into `MTL010` to `MTL013`.                                 | [spec 2.7](spec.md#27-inert-unknown-and-malformed-tags)                          |
| visitor             | An ANTLR object that walks a parse tree and returns a value. Here the tag visitors (`FamilyVisitor` in `src/tags/visitors/base.ts` and one subclass per tag family) and the helpers `BracketShapeVisitor`, `HeadingVisitor` and `DirectiveVisitor`. | [listeners and visitors](guides/grammar-and-listeners.md#listeners-and-visitors) |
